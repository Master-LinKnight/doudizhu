# 斗地主 — 绝对公平、AI 独立的桌面游戏

基于《斗地主-规则规格书与技术方案.md》开发。技术栈：Electron + React 18 + TypeScript + Vite + Vitest。

## 开发里程碑

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 规则引擎（三人 + 四人两副牌） | ✅ 已完成 |
| 2 | 规则算法 AI（三档难度） | ✅ 已完成 |
| 3 | 桌面 UI（Electron + React） | ✅ 已完成 |
| 4 | LLM 接入接口 + 降级 | ✅ 已完成 |
| 5 | 公平性验证 | ✅ 已完成 |

## 目录结构

```

  types.ts          牌型/模式/分析结果类型
  fairness.ts       可设种子随机（mulberry32，禁 Math.random）
  deck.ts           牌编码、洗牌（Fisher–Yates）、发牌
  hand.ts           牌型识别
  rules.ts          出牌合法性、大小比较
  engine.ts         游戏状态机（发牌→叫地主→出牌→结算）
  scoring.ts        计分与翻倍
  audit.ts          阶段 5：回放审计（replayGame / auditGame）
  ai/               阶段 2/4：规则算法 AI + LLM 可选接入
    isolation.ts     信息隔离（AiView/BidView 仅含自己手牌与公共信息）
    provider.ts      AiProvider 接口（decide / decideBid）+ 三档难度枚举
    decompose.ts     手牌拆解 / 候选牌型枚举 / 手数估值
    ruleAi.ts        三档难度决策（叫地主 + 出牌）+ RuleAiProvider
    llmProvider.ts   阶段 4：LLM 接入实现（可插拔 AiProvider，失败降级本地）
    simulate.ts      对局模拟器（纯函数，可回放）
src/renderer/       React 前端（阶段 3）
electron/           Electron 主进程（阶段 3）
tests/              单元测试
```

## 阶段 1 已实现的规则要点

- **牌编码**：单副牌 0..53，两副牌 copy*54 + singleId（0..107）；点数 3..17（16=小王 17=大王）。
- **牌型识别**：13 类标准牌型 + 四人天王炸；顺子/连对/飞机严格限定 3~A（不含 2 与王）。
- **大小比较**：普通牌型同类型（同长度）比点数；炸弹 > 普通；火箭 > 炸弹；天王炸 > 一切。
- **状态机**：叫分制（1/2/3，后叫严格更高，3 分封顶）、全不叫重发、首出/跟牌/过牌、春天/反春天。
- **计分**：底分 ×（炸弹/火箭/天王炸/春天/反春天各 ×2），地主与农民互为支付，零和。

### 对规则歧义点的实现口径（已按文档“无开放分歧点”原则确定）

1. **四带二**：规格书第 11 类含两种形态——`4 + 2 单`（6 张，两张单或一对）与 `4 + 2 对`（8 张，两对）。二者均按四张点数比较。
2. **四人同点数拆分**（第 10 节“6 张拆为 4+2”）：5~8 张同点数不作为单一牌型，`analyzeHand` 判为不合法；另提供 `splitSameRank` 返回 `bomb(4) + kickers(剩余)` 供 AI/UI 拆牌。示例：6 张同点数 → 炸弹(4) + 一对(2)。
3. **飞机带牌**：主体三张必须恰为 count===3 的点数且连续（3~A）；带单/带对数量与三张组数一致，带牌可为王，天然不与主体同点数。
4. **发牌顺序**：按座位逐人发满（块发），底牌为剩余；顺序不影响规则正确性，仅用于回放一致性。

## 阶段 2 已实现的 AI 要点

- **信息隔离**：`AiView`/`BidView` 只暴露「自己手牌 + 公共信息」，接口层面杜绝偷看/串通（`isolation.ts`，有专门测试断言不泄露他人手牌与底牌）。
- **三档难度**（`ruleAi.ts`，均为纯函数，随机仅经 `Rng`）：
  | 难度 | 策略 | 关键行为 |
  | --- | --- | --- |
  | easy | 贪心 + 随机次优 | 首出最小单张、跟牌压最小；含随机失误（可压却过） |
  | normal | 估值 + 一步前瞻 | 首出多张低点结构牌；跟牌出最省一手；保守保留炸弹 |
  | hard | 估值 + 前瞻 | 首出/跟牌选「剩余手数最少」一手；非被迫仅在手数 ≤2 时才用炸弹 |
- **候选枚举**：`decompose.ts` 的 `enumeratePlays`（首出候选）、`findBeatingPlays`（压牌搜索）、`estimateHandCount`（手数估值）复用阶段 1 的 `analyzeHand`/`beats`。
- **验收**：三档均能独立打完三人/四人整局，出牌全部合法（引擎对非法出牌抛错），结算零和；同种子同难度结果可复现。

## 阶段 3 已实现的桌面 UI 要点

- **界面流程**：设置屏（三人/四人模式 + 简单/普通/困难难度 + 特效开关）→ 牌桌（三/四座位、手牌、底牌、出牌区、结算浮层）。
- **出牌三按键**：`提示 / 不出 / 出牌`；`提示` 复用规则 AI（`decidePlay`，强制零失误）高亮推荐牌，`不出` 仅在有跟牌时可用，`出牌` 经 `isValidPlay` 校验。
- **牌型特效**（规格书第 5 节，开关 关闭/简化/完整）：基础牌型无特效；顺子/连对/飞机（combo）横幅提示；炸弹 flash+shake；火箭/天王炸 rocket+全屏。
- **AI 回合驱动**：`useEffect + setTimeout` 依次驱动非人类座位，人类固定座位 0（底部）。
- **Electron 壳**：`electron/main.ts`（ESM、无 preload、contextIsolation/sandbox 开启）+ `tsconfig.electron.json`；`npm run electron` 打包运行，开发期亦可 `npm run dev` 走浏览器预览。
- **桌面交互优化**：左上角「退出牌桌 / 重新发牌」按钮；操作按钮（出牌/不出/提示/叫分/不叫）居中置于手牌上方；叫分环节逐座位显示「叫 X 分 / 不叫」徽章 + 当前最高叫分摘要。
- **视觉与动画**：牌面放大至 105×150（迷你牌 64×90）、牌桌字号整体 +5px；发牌逐张落定（`dealIn`）与出牌飞牌（`playIn`）纯 CSS 动画；出的牌叠放（非摊开）；上一手出牌者金色高亮；手牌炸弹加红金边框 + 💣 角标。

## 阶段 4 已实现的 LLM 接入要点

- **可插拔 `AiProvider`**：接口扩展为 `decide`（出牌）+ `decideBid`（叫地主），本地 `RuleAiProvider` 与 `LlmProvider` 同构，默认走本地算法、完全离线可玩。
- **配置**：设置屏新增「AI 来源」（本地算法 / 接入 LLM）；选 LLM 时填写 API 地址、模型名、API key（本地无鉴权服务可留空）。
- **协议**：OpenAI 兼容的 `POST {baseUrl}/chat/completions`；手牌按下标编号（兼容四人两副牌的重复牌），prompt 明确身份与「禁止推断他人手牌做局」约束，难度档位通过 prompt 注入策略。
- **降级**：未配置 / 配置无效 / 网络异常 / HTTP 错误 / 超时 / 非法输出 / 出牌不合法，一律自动回退本地规则算法，保证对局不中断（有专门测试覆盖每种失败路径）。
- **测试连通性**：设置屏提供「测试连通性」按钮，向 `{baseUrl}/chat/completions` 发送最小请求（`max_tokens=1`），区分未配置 / HTTP 非 2xx / 网络异常 / 超时并展示结果。
- **配置持久化**：「AI 来源 + LLM 配置」保存到 `localStorage`，下次进入自动恢复、无需重复填写（apiKey 明文存储，桌面本地可接受）。
- **默认模型**：模型名默认预填 `deepseek-flash`。
- **信息隔离不破坏**：LLM 只拿到 `AiView`/`BidView`，每次决策独立调用、无会话状态，天然不串通。

## 阶段 5 已实现的公平性验证要点

- **回放审计**（`audit.ts`，纯函数）：`replayGame(mode, seed, log)` 由种子重发牌并按日志逐条重放；引擎对非法动作（越位叫分、出牌不在手、非法牌型、压不过上家等）一律抛错，故「能完整重放」即「每一步都合法」。`auditGame` 再核对：终态已结算、结算 winner/landlordWon/multiplier/scores 与日志一致、重放日志与原日志逐条相等。
- **多局异常检查**：三种难度 × 两种模式 × 多种子批量模拟，每局均 `auditGame` 通过、零和、无异常（规模 ≥100 局）。
- **信息隔离不被难度破坏**：三档难度 AI 的出牌只来自自己手牌，接口层面无法偷看他人牌。
- **信息隔离不被 LLM 破坏**：LLM prompt 仅含自己手牌与公共信息，负向测试断言不出现「对手独有、自己手上没有」的牌（含四人两副牌重复牌场景）。
